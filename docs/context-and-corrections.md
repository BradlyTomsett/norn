# API 上下文与纠错

生成、自动修复、一致性核对使用同一份请求资料，不在修复时重建一个缺少历史的提示。

| 资料 | 传递方式与优先级 |
| --- | --- |
| 引擎事实 | 当前日期地点、人物四维与六项技能、天赋免疫、实际装备、完整库存、账户、已结算账目、委托状态和本回合交易条件。数值由引擎决定。 |
| 玩家纠正 | 从新消息元数据和旧版“本回合纠正”原文恢复。事实纠正持续保存；仅针对本轮的禁用词不永久限制其他剧情。旧错误不得作为反证。 |
| 本轮要求 | 原始输入、解析出的选择、实际行动、纠错要求、待替换错误回复。纠错时最后一条用户消息只要求落实纠正，原行动只供定位。 |
| 近期对话 | 按 26,000 字符预算取完整轮次，能装下就全部发送，不再固定截取 14 条。去掉未选行动选项，保留正文完整结论。 |
| 长期事实 | 资料较少时发送全部有效知识与编年；较多时按当前行动、近期话题、活跃委托检索。搭档、队伍、分成、决定等带稳定 key 的重要约定始终保留。 |
| 较早原文 | 从未放入近期窗口的历史补充相关原文与相邻问答，最多 14,000 字符。整段保留，不截断到 1,100 字。 |
| 相关人物 | 固定编号、身份等级、性格、态度、已记录位置、同行标记及相关记忆。旧位置与未记录同行不等于“不在任务里”。同名人物不自动合并。 |
| 事实来源 | 区分亲历、他人说法、推断、玩家计划和未选建议。已被替代或与玩家明确纠正冲突的旧事实保留在存档里，但不再当作当前有效事实传递。 |

普通行动的候选回复在提交前额外核对人物、约定、本轮问题和变化数据。普通休息没有事实行动时省略这次核对；带纠错的休息仍核对。核对只能依据请求里的原文，必须给出可验证引用才能指出矛盾或遗漏；核对失败不提交。发现问题重写一次，再核对，仍不通过保留原进度。修复不能改交易、物品、数值或凭空增加行动。

人数与战斗力分别处理：实际成员按人计数，能力依据职业等级、技能、四维、装备和天赋。不能把低等级同伴算成半个人，也不能忘记已确认的搭档与分配约定。

新导出和云备份携带上一回合的纠错快照，用历史条数引用已有对话，不复制整份历史。旧文件没有快照时，可以保存事实纠正供后续使用，不能无依据重做已经结算的金额和时间。连续纠错累计先前要求，替换原回合而不是推进新回合。

诊断只新增上下文字符数、历史条数、召回条数和纠正条数，不记录请求正文、对话、密钥。必要资料超过 100,000 字符时停止发送并提示缩小本次范围，不静默丢掉关键条件。

## 场景承接与旧纠错

明确取消的动作会在后续请求中继续约束叙事；玩家主动重新提出该话题后解除。旧回合里被否定的片段和同一回合由此产生的相关知识不会作为已发生的事实发送，原始存档和历史仍保留。仅限本回合的明确要求按其范围处理。不同时间的人数纠正按最新记录生效。

发送资料时加入当前场景、最近实际叙述、委托和接洽原文、相关人物及其知情边界。旧存档的地点与明确进入场所的叙述冲突时，保留可追溯线索并标记地点待核对，不在读取时擅自改地点；确认地点后正常更新。新回复明确写进了新地点但遗漏 location 时走已有的一致性修复，不能额外增加移动或改变既有结算。

同名人物的旧编号若缺少身份依据，不强行归到某个人；能够通过同一任务内的身份和共同参与原文交叉核对时，仅在本次请求中带上有来源的身份提示。人物知情需有本回合可验证的告知、听到或亲口说出证据。旧约定的替换需要本回合原文依据和相同主题，证据不足的新说法标记待核实，不覆盖原约定、不触发基于已确认知识的后果。
