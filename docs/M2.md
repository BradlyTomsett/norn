# M2：简化状态与持续世界

## 人物与关系

人物保留健康和文字心情。旧存档载入时移除疲劳、饥饿、伤病、压力与士气，保留原有天赋、能力、资产和自定义月钱。普通出身不再自带贵族月钱。装备与库存完整保存，显示或上下文上限不会删除物品。

状态 → 关系：每个人物都显示信任、亲近程度，最终范围 −100～100。−100 红色，0 白色，100 绿色，中间连续渐变，同时有数字和位置标记。

NPC 的目标、进展、互动记忆和下一行动日期随存档保存。玩家已做出的选择可以产生延迟后果，到期改变关系、声望或人物处境。线索页记录后果和起因。隐秘计划不会提前显示。

## 回合、交易与纠错

回合在副本上运行，完整回复及结算验证通过后才一起保存人物、对话、回执与纠错检查点。断线或无效金额保留待处理回合，原日期、余额和库存保持原样。交易与委托使用固定编号，同一回合重试不会重复付款。领赏和队友分成整笔验证。

| 操作 | 作用 |
|---|---|
| `/状态`、`/时间` | 本地查看，不消耗回合或模型请求 |
| `/存档` | 立即保存本地进度 |
| `/纠错 具体说明` | 从上一回合结算前重新处理，以新结果替换原结果 |
| `/撤回` | 回到上一回合结算前 |
| “重试本回合”或 `/重试` | 重试尚未提交的回合，保持同一回合编号 |
| `/取消重试` | 放弃未提交草稿，保留原进度 |
| “从这里另开分支” | 建立保留完整历史的新存档 |

旧存档没有回合检查点，首次载入时无法撤回旧版历史；完成一个新回合后即可使用纠错。此前发生的错误不会凭空补发金钱，需要核对原记录后再修正。

## 游戏物价与存档物价

游戏物价直接读取 `engine/economy.js` 的既有物件、活计及估价规则，不复制进每份存档。包括跑腿/捎话/送信、打杂/帮工、向导、盯梢、情报、抄写、表演、护送、赌桌等参考范围。

存档物价只补充游戏尚未收录的常用物件和服务。状态 → 物价页可以展开只读的游戏参考，编辑这份存档的补充条目。两套表都供 AI 生成报价参考，实际成交仍按本次数量、品质、路程、风险与商谈金额结算，不把一次成交或赏金自动固定为永久参考价。

已撤销的错误邮资会在载入旧存档、导入备份及保存对话时清除，也不能重新加入参考表或用于结算。清理历史报价与账目文字不会改动现有余额。

## 存档、云备份与更新

本地、文件导出与云端使用同一版本化存档包，并保留完整对话。兼容旧版仅有角色状态的 JSON。浏览器空间不足时拒绝新回合并保留旧存档，可以先导出或清理旧分支。

云备份按同一存档排队，并核对上次保存的版本。同一份旧进度可以安全衔接新格式；遇到另一设备的不同进度时停止覆盖，可以恢复为新副本或建立快照分支。

设置中可以选择“仅本次会话保存 API Key 与 GitHub 令牌”。凭据不会进入存档包。应用更新等待正在进行的回合结束，离线资源按完整版本缓存。

## 开发与验证

使用 Node.js 22 或更新版本，无第三方运行依赖：

```text
npm test
npm run build
node tools/preview.mjs
```

`npm test` 运行浏览器兼容的原有检查和模拟流程测试。`npm run build` 生成内容指纹、完整离线资源清单和仅含游戏运行文件的 `dist/`。GitHub Actions 在 PR 与正式部署前执行检查，发布 `dist/`，不发布测试、开发工具或凭据文件。

`node tools/preview.mjs --fixture` 提供独立虚构测试存档与模拟模型响应，用于界面、断线、重试和纠错检查。该模式阻止模型与云存档的真实请求，不使用真实 Key 或存档。默认预览端口为 18974，可用 `NORN_PREVIEW_PORT` 调整。

机器协议位于 `engine/protocol.js`；持久目标及后果位于 `engine/npcs.js`。提示词背景、叙事风格和机器协议分开维护，字段与单位以机器协议为准。
